# PLAN.md: планировщик (Telegram-бот + Mini App)

Дедлайн: **31 декабря 2026**. Рабочий MVP: **~15–20 ноября**. Остальное: полировка, бета на себе, буфер.
Задачи для ИИ-агента пронумерованы (`T1.2`). Промпт для агента формируется под каждую задачу отдельно.

## 1. Принятые решения

1. **Модульный монолит**: общий пакет `core` (модели, репозитории, фасады); `api` (FastAPI) и `bot` (aiogram + APScheduler) отдельные процессы поверх него. HTTP между ботом и API нет.
2. **Слои бэкенда**: Router -> Pydantic-схемы (роль «презентера»: валидация и DTO) -> Facade -> Repository -> PostgreSQL. Отдельного Presenter нет.
3. **Миграция с SQLite на PostgreSQL**. Текущий прототип (`aiosqlite`, сырой SQL, `planner.db`) заменяется целиком; данных для переноса нет.
4. **Привычки**: период `week`/`month`/`year`, потолок цели 7/31/366. Одна галочка = одна запись с датой, не больше одной в день.
5. **Задачи**: `deadline` только датой; `urgency` и `importance` 1..3 (матрица Эйзенхауэра); статусы `active`/`done`/`cancelled`.
6. **Рефлексия**: `kind = topic | daily_review`, необязательное настроение `mood` 1..5. Итоги дня это рефлексия вида `daily_review` (одна в сутки).
7. **Фронтенд**: серверные данные только в TanStack Query; MobX только для клиентского состояния (сессия, вкладка, фильтры, черновики, модалки).
8. **ChatGPT** в первой версии только для генерации тем рефлексии (пул в БД + резервный список).
9. Redis: rate limiting (и FSM при необходимости). Не кэш.
10. Long polling, один экземпляр бота, один шедулер.

## 2. Контракт API (v1)

Префикс `/api/v1`. Все эндпоинты кроме `/auth/telegram` требуют `Authorization: Bearer <JWT>`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/telegram` | `initData` -> JWT, upsert пользователя |
| GET / PATCH | `/me` | профиль, таймзона, время напоминаний |
| GET / POST | `/tasks` | список (фильтры: `status`, `deadline_from/to`, `limit`, `offset`) / создание |
| GET / PATCH / DELETE | `/tasks/{id}` | чтение / изменение (в т.ч. смена статуса) / удаление |
| GET / POST | `/habits` | список с галочками за текущее окно периода (`?on=YYYY-MM-DD`) / создание |
| PATCH / DELETE | `/habits/{id}` | изменение (в т.ч. архивация) / удаление |
| PUT / DELETE | `/habits/{id}/checks/{date}` | поставить / снять галочку (идемпотентно) |
| GET / POST | `/reflections` | список (`kind`, `limit`, `offset`) / создание |
| GET / PATCH / DELETE | `/reflections/{id}` | CRUD |
| GET | `/reflections/random-topic` | случайная тема из пула |

Фронтенд получает TS-клиент генерацией из OpenAPI (`orval` или `openapi-typescript`).

## 3. Лимиты (стартовые значения, `core/limits.py`)

| Что | Значение |
|---|---|
| Активных задач на пользователя | 200 |
| Привычек (не в архиве) | 20 |
| Рефлексий на пользователя | 500 |
| Максимум на странице списка | 100 |
| Длина названия задачи / привычки | 200 / 100 |
| Длина описания задачи | 2000 |
| Длина текста рефлексии | 5000 |
| Дата галочки | не в будущем, не старше 370 дней |
| Запросов в минуту на пользователя | 120 (на `/auth/telegram` строже) |
